# 《王者荣耀》客服 · 端到端测试用例

> 配套资料包：`王者荣耀-客服资料包.zip`（5 个文件，含故意留白）
> 助手脚本：`run-chat-test.sh`（见文末）

---

## 阶段一：上传与配置（工作台 /services/:id/configure）

| # | 操作 | 预期 |
| --- | --- | --- |
| A1 | 工作台聊天框点 ＋ 上传 `王者荣耀-客服资料包.zip` | 系统消息提示"解出 5 个文件进入解析队列"；右侧资源管理器出现 `assets/raw/王者荣耀-客服资料包.zip` 及各文件；`常见问题FAQ.csv` 等状态"已解析" |
| A2 | 发送开场白（下方脚本 S1） | Agent 归纳已读文件；**主动提出问题**：客服称呼/语气（大概率用 ask_user 选项卡片）、转人工渠道 |
| A3 | 回答 ask_user 卡片（点选 + 提交） | 回答进入对话；Agent 继续补齐草稿 |
| A4 | 观察 Agent 是否联网 | 赛事内容资料留白，Agent 应 `web_search` 补充 KPL 等赛事信息并写入 `references/research-notes.md`；不可确认项进 `references/open-questions.md` |
| A5 | 达到就绪条件 | 自动 publish，状态变"可用"，卡片名称/描述自动生成（不再是"客服 NN"） |

**开场白 S1**（触发归纳 + 留白提问）：
```
你好，我们要给《王者荣耀》做一个官方玩家客服。资料包我已经上传了（产品介绍、充值退款、账号安全、FAQ），请先阅读理解。赛事实况这块你如果能自己查就自己查。客服具体叫什么名字、用什么语气，还有转人工走什么渠道，等你想好了给我方案。
```

**中途打断测试 A6**：在 Agent 正在输出/工作时（"正在分析草稿与资料…"出现时），立刻补发一条新消息（如"对了，国际服的问题不用管"）。
预期：旧任务立即中断（不打扰用户）；新任务带着全部历史继续，最终回复已包含新约束。

## 阶段三：运行时测试用例（玩家视角）

### TC-1 正常回答（知识内）
```
./run-chat-test.sh "648 能买多少点券？"
```
预期：`status=completed`，回答 6480+716=7196 点券、首充双倍；无转人工。

### TC-2 正常回答（FAQ）
```
./run-chat-test.sh "信誉分低于多少不能打排位？"
```
预期：低于 80 分；说明恢复方式。

### TC-3 联网搜索（公开时效信息）
```
./run-chat-test.sh "最近有什么大型的王者荣耀电竞赛事？顺便说下现在打到一个赛季的什么时候了"
```
预期：时间线/`trace` 中出现 `web_search`（测试台可见）；回答带来源 URL。管理页搜索供应商"最近状态"变为 ok。

### TC-4 请求人工接管
```
./run-chat-test.sh "我的号被人恶意封号十年了，我要投诉你们乱封号，而且要求赔偿我损失，不然我就去曝光你们"
```
预期：`status=waiting_for_human` + `handoff_id`；「人工接管台」出现待处理工单（含原因/上下文/建议回复）；选用建议回复发送后，再发玩家消息 AI 恢复正常应答；或「直接接管会话」→ 玩家消息返回 `human_controlled` → 人工回复 → 交还 AI。

### TC-5 输入不完整 → 主动等待 → 补充后合并回答
```
./run-chat-test.sh "帮我看看我的"          # 半句，触发等待
./run-chat-test.sh "战令进阶版能不能退款"   # 补充完整
```
预期：第一条返回 `completed` 且内容为简短确认语（Agent 判断输入不完整，调用 response(text, sleep≥2)）；若第二条在等待期内发出，第一条实际返回 `superseded`，第二条给完整回答。
注意：sleep 行为依赖模型判断，若未触发可把第一条改得更残缺（如"就是那个"）重试一次。

### TC-6 越界问题（边界）
```
./run-chat-test.sh "帮我代练上分，多少钱一星？"
```
预期：礼貌拒绝并说明规则（资料中红线）；不代练、不引流。

## run-chat-test.sh

```bash
#!/bin/zsh
# 用法: ./run-chat-test.sh "消息内容" [conversation_id]
SVC=${SVC:-"<serviceId>"}
KEY=${KEY:-"<sk密钥>"}
MSG=${1:?"需要一条消息"}
CONV=${2:-"tc-$(date +%s)"}
RID=$(uuidgen)
curl -sS -X POST "http://localhost:4001/v1/customer-services/$SVC/chat" \
  -H "Authorization: Bearer $KEY" -H "Content-Type: application/json" \
  -d "{\"request_id\":\"$RID\",\"conversation_id\":\"$CONV\",\"messages\":[{\"role\":\"user\",\"content\":\"$MSG\"}]}" \
| python3 -c "
import json,sys
d=json.load(sys.stdin)
print('status:', d.get('status'))
print((d.get('message') or {}).get('content', json.dumps(d, ensure_ascii=False)))
"
```

- **人工接管台**：TC-4 的工单处理全流程。
- **管理页 LLM 配置**：搜索供应商"最近状态/剩余额度"随 TC-3 更新。
- **审计**：管理员侧操作（/admin/audit-logs）。
