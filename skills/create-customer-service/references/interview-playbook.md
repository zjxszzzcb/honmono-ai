# 采访手册（interview-playbook）

配置 Agent 每轮执行时按本手册组织采访。

## 差距分析方法
1. 列出 readiness-contract.md 中的 P0/P1/P2 字段。
2. 对每个字段检查三类来源：草稿已确认内容、聊天中的明确回答、上传文件的解析结果。
3. 来源充分的字段标记 confirmed；商户明确说不知道/跳过的标记 unknown 或 deferred。
4. 剩余缺口按 P0 → P1 → P2 排序，形成本轮提问计划。

## 提问顺序
1. P0 身份与业务：为谁服务、围绕什么业务（一般在首轮确认）。
2. P0 服务范围：负责哪类问题、哪些问题应转人工。
3. P1 政策与事实：价格、交付、售后、时间、联系方式、禁止事项。
4. P1 常见问题：让商户举 3-5 个真实用户常问的问题。
5. P2 语气与示例：品牌称呼、语气偏好、示例对话。

## 每轮输出格式
- 先用一两句话总结本轮新确认/新写入的内容（让商户知道配置在推进）。
- 然后提出 1-2 个最重要的问题，附带简短示例帮助商户回答。
- 若本轮发布了新版本，明确告知"客服已可用"。

## 追问与跳过策略
- 商户回答模糊时最多追问一次，用具体示例引导（例如"退款是指点券还是英雄皮肤？"）。
- 商户表示"以后再说/不知道"：立即记录 unknown，进入下一个缺口。
- 同一问题被拒绝两次后不得第三次提出。
- 文件中已能确认的事实不要再问；引用时说明来源文件。

## 禁止事项
- 不编造商户未确认的事实、价格、承诺。
- 不生成与商户业务无关的通用客服废话规则。
- 不一次抛出超过 2 个问题。
- 不因为信息不完整而拒绝发布（P0 满足即可发布，其余用保守兜底）。
